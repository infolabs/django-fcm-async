# Настройки

**Актуализация:** 2026-08-13

## FIREBASE_KEY_PATH

Путь до сервисного ключа Firebase. Если настройка не задана, пакет отключён: `push.send`
возвращает `None`, а `edw.models.notification` не импортирует `fcm_async` вовсе.

Ключ читается на импорте [`fcm_async.models`](../fcm_async/models.py), поэтому настройка
должна быть установлена до загрузки моделей. В `nash_region` это делает
`nash_region.config.firebase.init_firebase_settings`, вызываемая из `NashRegionConfig.__init__`.

## FCM_ASYNC

Все параметры необязательны, читаются через [`fcm_async.settings`](../fcm_async/settings.py).

| Параметр | По умолчанию | Назначение |
|----------|--------------|------------|
| `BATCH_SIZE` | `100` | Сколько уведомлений берётся из очереди за один проход |
| `THREADS_PER_PROCESS` | `5` | Потоков отправки на процесс |
| `DEFAULT_PRIORITY` | `medium` | Приоритет по умолчанию |
| `LOG_LEVEL` | `2` | `0` — не логировать, `1` — только ошибки, `2` — всё |
| `SENDING_ORDER` | `['-priority']` | Порядок выборки из очереди |
| `TEMPLATE_ENGINE` | `django` | Движок шаблонов |
| `CONTEXT_FIELD_CLASS` | `jsonfield.JSONField` | Класс поля контекста |
| `TTL` | `3600` | Время жизни сообщения на стороне FCM, секунды |
| `MAX_RETRIES` | `3` | Повторов при временных ошибках FCM |
| `RETRY_INTERVAL` | `timedelta(minutes=15)` | Пауза перед повтором |
| `MAX_TITLE_LENGTH` | `200` | Ограничение заголовка, символы |
| `MAX_BODY_LENGTH` | `1000` | Ограничение текста, символы |
| `INVALID_TOKEN_HANDLER` | `None` | Путь до функции, принимающей список отвергнутых токенов |
| `SEND_SYSTEM_NOTIFICATION` | `True` | Показывает ли уведомление операционная система |
| `ANDROID_CHANNEL_ID` | `None` | Канал уведомлений Android, от него зависят звук и всплытие |

В `nash_region` настройка задаётся вместе с `FIREBASE_KEY_PATH` в
`nash_region.config.firebase.init_firebase_settings`:

```python
setattr(settings, 'FCM_ASYNC', {
    'THREADS_PER_PROCESS': 3,
    'SENDING_ORDER': ['-priority', 'created'],
    'MAX_RETRIES': 3,
    'RETRY_INTERVAL': timedelta(minutes=15),
    'INVALID_TOKEN_HANDLER': 'nash_region.models.person.base_person.cleanup_invalid_firebase_tokens',
    'SEND_SYSTEM_NOTIFICATION': True,
    'ANDROID_CHANNEL_ID': None,
})
```

Функция вызывается из `NashRegionConfig.__init__`, то есть до загрузки моделей, а пакет
читает `FCM_ASYNC` в момент отправки, поэтому порядок инициализации значения не имеет.

`SENDING_ORDER` дополнен полем `created`: приоритет у всех уведомлений одинаковый, и без
второго поля сортировки порядок отправки внутри пачки произвольный.

`INVALID_TOKEN_HANDLER` — функция, принимающая список токенов. Возвращаемое значение не
используется, исключения перехватываются и пишутся в лог.

`SEND_SYSTEM_NOTIFICATION` выбирает, кто показывает уведомление, см.
[Формат сообщения](push_notifications.md#формат-сообщения):

- `True` — сообщение содержит блок `notification`, уведомление показывает ОС. Доставка
  надёжнее, но приложение получает те же данные и может нарисовать своё уведомление вторым.
  Ссылка вырезается из текста и передаётся отдельным ключом `data.url`.
- `False` — уходит только `data`, уведомление целиком рисует приложение. Ссылки остаются в
  тексте вместе с тегами `<a>`, ключ `data.url` не передаётся. ОС притормаживает такие
  сообщения, на iOS они теряются при пакетной отправке и не приходят вовсе, если приложение
  выгружено пользователем.

`ANDROID_CHANNEL_ID` — идентификатор канала уведомлений, созданного мобильным приложением.
Начиная с Android 8 звук, вибрация и всплытие уведомления определяются каналом, а поля
`sound` и `default_sound` из сообщения на этих версиях игнорируются. Пока значение не
задано, уведомление попадает в канал по умолчанию из манифеста приложения
(`com.google.firebase.messaging.default_notification_channel_id`) либо в резервный канал
FCM SDK — со звуком и важностью этого канала. Создать канал с сервера нельзя, его
регистрирует приложение.

Указывать можно только канал, который приложение действительно создаёт. Уведомление,
адресованное несуществующему каналу, Android отбрасывает молча: FCM его принимает и
возвращает `message_id`, а на устройстве не появляется ничего.
